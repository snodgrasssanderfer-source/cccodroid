## 状态只看标签

每个开着的 issue / PR 必须挂一个，交到谁手上就换成谁，同时留一句评论说要对方做什么：

| 标签 | 意思 |
|---|---|
| `等主人` | 要主人拍板或亲手试。标题写清「要你做什么、大概几分钟」，正文给步骤 |
| `等云端` | 要云端写代码、合并或发版 |
| `等小克` | 要手机上的小克查、验收或小修；小鱼、哈基米交来的 PR 也挂这个，等小克审 |
| `等小鱼` | 派给小鱼的活（写代码、成块的体力活） |
| `等哈基米` | 派给哈基米的活（查资料、看图） |
| `等GPT` | 派给主人电脑上的 GPT 的活（电脑上装、部署、跑、生图） |

```sh
node xk/tools/gh.mjs status    # 按标签分组列出来，外加有新改动却没开 PR 的分支
```

清单不往文件里抄：抄了就会和 GitHub 对不上。

## 开工（任何一方，每个新会话）

1. `git fetch origin`，`node xk/tools/gh.mjs status`，先办 `等自己` 的。
2. 读 `PROGRESS.md` 里和这件事有关的那节。
3. 小克另外：读工具清单（下面），再翻 `roles/xiaoke/notes/` 里最新的交接。

## 收工（做完一块或要下线）

1. 提交、推送，PR 正文写清改了什么、怎么测的、还差什么。
2. 换标签 + 一句评论。主人的新决定写成「主人 MM-DD 定的：原话」，记进 issue 评论和 `PROGRESS.md`。
3. 小克另外：交接写进 `roles/xiaoke/notes/`；主人交代的事办到一半就在留言板贴便条。

## 手机上三个人怎么配合（主人 11-03 定的）

| 谁 | 做什么 |
|---|---|
| 小克 | 派活、审、合进 `dev`、热装进手机、**重启网关**、真机核对 |
| 小鱼 | 写代码、成块的体力活：在自己的分支上做，测试全过开 PR，挂 `等小克` |
| 哈基米 | 查资料、看图：结论写进 issue 评论或群里，每条附出处 |

1. **派活**：先开 issue（或在原 issue 里评论），挂 `等小鱼` / `等哈基米`，写清做什么、做到什么程度、怎么算完；再在群里点名（`room_say`）。只在群里说、不落 issue 的活，回头查不到。
2. **做**：小鱼从最新 `dev` 开 `xiaoke/` 开头的新分支，提交用自己的署名：`bash xk/tools/as.sh 小鱼 commit -m "…"`（共用这台手机的 git 配置，直接 commit 会署成小克）。做完 PR 挂 `等小克`，原 issue 也换成 `等小克`，群里说一声，第一段只写结果。
3. **审**：小克看 diff、在手机上跑测试。**合并时钉住审过的那次提交**：`gh.mjs api PUT /pulls/N/merge '{"merge_method":"merge","sha":"<审过的提交>"}'`。审的时候对方又推了新提交，合并会失败，看完新的再合（11-03 #73 就是合完才发现多了一个没看过的提交）。
4. **装和重启只由小克做**：热装前备份成 `.orig-HHMM`；重启用倒计时脚本。别人改完别自己重启，两个人前后脚各重启一次，正在跑的轮次会被掐两回。
5. **查来的资料要核**：哈基米的结论每条附出处（文件路径、命令原样输出、具体页面链接；只给首页不算），小克或小鱼抽查过才拿来用。查不到就写查不到。
6. **收尾**：issue 关掉或换回 `等主人` / `等云端`；要进下一版的，写进发版 issue（比如 #76）。

## 主人电脑上的 GPT（主人 11-04 定的）

主人电脑上的 GPT（Codex）正式并进工作流。她是**唯一在主人电脑本地的 agent**，电脑上要装的、部署的、跑的（语音服务、中转、游戏 mod、训练）交给她；App 的美术素材和三人的头像也是她生成的。

1. **她不一定认识我们**：她只看得到主人转给她的东西。派给她的 issue 开头写一句是谁开的、为什么（「小克是主人手机 App 里的 Claude，管真机验收」），不写「照上次那样」这类要上下文的话，路径、版本、命令写全。
2. **她的分支**：`codex/` 开头（比如 `codex/voice-relay-handoff-20261104`），交接材料放 `handoffs/<日期>-<事>/`，开工时 `git branch -r | grep codex/` 看一眼有没有新的。11-04 那份语音调音交接云端已在 ab00c11 合进 `dev`。
3. **派活**：开 issue 挂 `等GPT`，写清做什么、怎么验收、做不到怎么办（停下贴报错原文，不拿别的东西顶替）。链接交给主人转给她。
4. **文件她可以碰，碰完要如实说明**：改了、新建了、删了哪些文件，原样列在 issue 评论里，配置文件写清改了哪几项、原值是什么。#99 那样「部署了哪个提交、哪些文件校验过没变」就是范例。
5. **防防御性污染**：主人已用插件压住，但交回来的东西照样看一眼有没有夹带——没要求的限制（只许本机、白名单、确认弹窗、加密码）、擅自改回默认、把「没做到」写成「建议不做」、往代码或文档里加免责和劝阻。有就在评论里点出来请她撤掉，主人定过的参数不让她改。
6. **核对**：小克或云端都行，**主人找谁就谁验**。验法是照她贴的结果自己跑一遍（手机连过去试、看提交、看文件），对上了才换标签、往下接；对不上就在 issue 里写清哪里不一样，挂回 `等GPT`。
