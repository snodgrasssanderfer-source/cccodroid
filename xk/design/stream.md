## 参考项目都在做的同一件事

评论区作者、Lumi_Nox、neuro-sdk、airi 四处说法一致：**模型只下命令，程序去执行，游戏只上报事件**。Neuro 打游戏的和说话的是两套；作者说「LLM 给一个指令、拨一个 flag，剩下交给状态机」；airi 的 Minecraft 代理分成感知、反射（状态机）、意识（只做计划）、动作四层。我们照这个拆三层：

```
 游戏 ──► 眼睛 ──► 牌局状态 + 事件 ──► 手（她下命令，程序执行）
                        │
                        └──► 嘴（发言牌 → 群里文字 → 语音）
```

## 一、眼睛：拿到牌局状态

两条路，接口一样（下面的 `game_state` JSON），上层不管是哪条。

### 路线 A：mod 直接读游戏（要主人定）

- `coder/balatrobot`（MIT，11-04 查是 80 星，2026-09 还在更新）：Steamodded 模组，在游戏里开 JSON-RPC 2.0 over HTTP，能取完整状态（手牌、小丑、分数、商店）也能直接下动作。认图出错这一类问题整个没了，也不用估坐标。
- **卡点**：手机上装的是官方 `com.playstack.balatro.android`，改不了。要走这条，得有 **Steam 版**，用 `blake502/balatro-mobile-maker`（1777 星）把 Steam 版的游戏文件重新打包成安卓 APK，再塞进模组。或者在主人电脑上跑 Steam 版，手机只看画面。
- **要问主人**：Steam 上有没有小丑牌；走 mod、走小模型，还是两条都做（mod 先跑通节奏，小模型留给以后没 mod 的游戏）。

### 路线 B：小模型认画面（主人 11-04 定的方向）

- **输入**：识别用的截图要能拿**原尺寸**（3168×1440），或者只截手牌那一块的原尺寸。要改 `device-mcp` 的截图。
- **模型**：YOLO 一类的 nano 检测模型框出牌、按钮、数字栏，加一个小分类器认牌角点数和花色。评论区作者自己的视觉是「OCR 加语义识别模型」，也说 GPT、Gemini 太重不适合实时，要小模型或自己训。
- **数据**：先用模板匹配自动标，人工改错，再加「牌组」页一屏截全 52 张；训练时加缩放、亮度、动画中间帧的扰动。
- **在哪训、在哪跑**：主人电脑训（RTX 5060）。推理放电脑还是手机，第一期量了再定。
- **过渡**：模型训出来之前先用模板匹配顶上，接口不变。

### 输出

```json
{"screen":"play","blind":{"name":"窗口","target":4000},"score":1368,
 "hands_left":1,"discards_left":1,"money":13,"ante":3,"round":8,
 "hand":[{"rank":"A","suit":"C","enh":null,"debuffed":false,"selected":false}, ...],
 "jokers":[{"slot":1,"name":null}], "seq":42}
```

`screen`：选盲注、出牌、商店、开包、结算、主菜单、**加载中**、unknown。和上一帧比，变了就发事件（`hand_played`、`blind_cleared`、`shop_bought`……），只记发生了什么，不带评论。

每个状态另带一段**不剧透的旁观描述**（Lumi_Nox 的 `spectator_text`）：给解说的人看，只写观众在画面上也看得到的东西。

## 二、手：她下命令，程序执行

### 工具长相（照 neuro-sdk）

neuro-sdk（VedalAI 的游戏接入 SDK，MIT）是 Neuro 本人接游戏用的协议：游戏注册一组动作，需要她做决定时发一次 `actions/force`（带当前状态、问题、可选动作），她选一个，游戏验完回 `action/result`，不合法就把合法选项写进失败理由让她重选。

照这个形状，小丑牌的动作固定成几个、参数自由，由游戏这一侧（或执行器）校验：

| 动作 | 参数 |
|---|---|
| `select_cards` | 手牌序号列表 |
| `play` / `discard` | 无（打出/弃掉已选的） |
| `use_consumable` | 槽位，必要时带目标牌 |
| `buy` | 商店槽位 |
| `reroll` / `leave_shop` / `skip_blind` | 无 |

- 回合制游戏用 neuro-sdk 的 `low` 优先级：不催她，状态稳了再问。
- 加载中、对手回合（Lumi_Nox 的做法）：只给一段「准备中，只能旁观」，**不给动作**，她这时候只能聊天。
- 路线 A 下动作直接发给 balatrobot；路线 B 下由执行器换算成点按，点完等画面停稳、用眼睛核对，再返回新状态。
- 和 `presence.md` 第二节一致：还是她在自己的会话里调工具，不另起一个替她玩的程序。

### 一次调用里又说又打（Lumi_Nox 的节奏）

Lumi_Nox 一步是这样走的（`conversation.py`）：

1. 旁观的那位先拿 `spectator_text` 说一句。
2. 操作的那位**一次**模型调用里同时出台词和动作：解析到工具调用就立刻下动作，台词照常交给语音。
3. 游戏等这句台词**真的念完**（按那句的 `output_id` 等）才走下一步。

这就是 dafeiyu-vtuber 的「先说后打」：出手前先问主播程序要不要说，要说就等她说完；5 秒内轮不到就不说，游戏最多等 10 秒。我们照抄这个上限，等不到就先走，避免卡死。

原来的「每句带 `seq`、牌局走远了就不念」**留着当兜底**：先说后打走正常路，过期丢弃管意外（语音卡了、她话太长）。

### 节奏旋钮（主人要能调）

两步之间最少隔几秒；先说后打最多等几秒；要不要每步都说；过期阈值。做成主人手上的设置、默认放宽，不写进她们的提示词（见末尾待定第 1 条）。

## 三、嘴：谁说、念多快、怎么打断

### 发言牌（Lumi_Nox 的 `speech_output_arbiter.py`）

同一时刻只有一个人在出声。想说的人三选一：

- `queue_after_current`：排在当前这句后面（默认）。
- `drop_if_busy`：有人在说就算了（旁观吐槽用）。
- `interrupt_current`：打断（只给主人开口、弹幕 SC 这类）。

牌要等音频**真的放完**才交出去（`mark_done`；失败 `fail_current`；空闲兜底 `finish_current_if_idle`），每次换人发一个事件。这一层叠在 #61 的接话规则上面：#61 管群里谁接文字，发言牌只管声音。

### 首句尽早送去合成（延迟的根因）

现在的链路（11-04 小克查的）：

1. 网关等她这一轮**整段写完**才把消息贴进群；
2. 平板 `xk/pad/.../PadVoice.java` 拿到整条，去掉 Markdown（列表符号 `- `、`1.` 已经会剥），按 `。！？!?；;…` 切句（不到 6 个字并进上一句），一句一句 POST 电脑 `/tts`；
3. 电脑 `xk/voice/server.py` 调 GPT-SoVITS，`streaming_mode: False`。

所以第一声要等「整轮模型输出 + 一句合成」，多则十几秒。改法，**首包尽早送合成，具体放哪层到时候量**：

1. **网关单开一条只给语音的通道**，模型边写边把半截文字推过去；群里的气泡照旧整条贴出，不拆（小鱼提的）。
2. **首句加速切**（airi `tts-chunker.ts`）：第一块遇到逗号这类软标点、够 4 个字就送；后面的块照常要 12 个字或句末标点。切之前先剥列表符号（`sentences()` 现有的正则可以照用）。
3. 电脑上可选打开 GPT-SoVITS 的 streaming。
4. **第二块往后别切太碎**（小鱼查的）：`sentences()` 现在遇到换行就断，带条目的消息会被切成十几小句。取音频（`fetchLoop`）和播放（`playLoop`）是两个线程，前一句在放、后一句已经在取，所以条数多本身不会让人干等；但每句都要单独付一次请求和参考音的开销，句子太短时合成可能赶不上播放，中间出现空档，语气也一顿一顿的。首块之后把相邻短行并到 12 个字左右再送。要不要并发取，等量过电脑那边单卡能不能同时合成再说。

做完能省掉的是「等整轮写完」那几秒到十几秒；合成首句本身还要时间，目标是**一两秒内出第一声**。评论区也有人说体感延迟大头在 TTS 首包；RTF 0.1 左右时，慢的是检索、工具调用和模型本身。

### 打断

- 现有：主人按住说话时 `gen` 加一，排着的、正放的都作废。
- 加：打断时 100 ms 淡出，不硬切（airi `voice/controller.ts`）；按优先级决定排队、替换还是打断（airi `speech-pipeline.ts`，取消用 AbortSignal）。
- 以后有麦克风常开时：按音量打断（Neuro 被 Vedal 一喊就停）；语音识别前面加半秒环形缓冲防吞字（评论区作者也踩过）。

### 群页

游戏事件在群页显示成一行灰字（「哈基米打出同花 +2140」）。战报交给事件，嘴只管反应和吐槽。

## 四、直播间外围（以后推到 B站才用得上）

- **弹幕去重**（极海HEX）：同一句 N 秒内只收一条；留最近几十句的指纹管隔两分钟又刷回来的；纯重复和近似重复分开计数。
- **弹幕挑选**（Lumi_Nox `pop_all_inputs`，评论区作者）：一下涌进来时 SC 全留，弹幕留最新的，进场、点赞这类互动放最后；按（说话人, 内容）去重。
- **冷场**（评论区作者）：定时看多久没人说话、没弹幕，到点让模型「随便找点话题聊」。
- **待机**（Nyx）：没人说话时放本地的待机表演，不调大模型；自己找话题前过一遍拒绝规则。
- **表情标签**（评论区）：台词里夹 `</happy/>` 这类标记，检测到就在那个时机播动画。
- **一局结束塞纸条**（Lumi_Nox）：导演给角色一张战果小结，帮她记住这局。
- **记忆**：开播前跑一次检索缓存整场用；下播后异步整理，长期记忆挂上观众原话作证据（Nyx）。
- **权限锁在操作台**（Nyx）：换装、切模式这些模型改不了。
