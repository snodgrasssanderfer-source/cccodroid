## 11-04 下午这一局看到的问题（真机）

哈基米第一次用原生工具打小丑牌（接主人的存档，第 3 底注 Boss「窗口」），小克、小鱼在群里看：

- **慢**：每一步都是「截整屏 → 模型认图 → 估坐标 → 点 → 再截图」。哈基米每次调模型 6–8 秒（11-02 量过），选 4 张牌再点弃牌要 5 次点按、5 个来回。
- **认图会错，而且谁都会错**：小克两次在群里说她把方片 10 认成了红桃，后来把牌角裁出来放大一看，是小克看错了：那张是红桃，它被削弱是因为涂抹小丑让红桃和方片算同一种花色。缩到 1280 宽的整屏图上，牌角只有 20 来个像素。
- **玩和说拴在一起**：她点一下、写一大段战报、这一轮结束，要等群里有人接话才走下一步。语音念完一段，牌局已经变了。每轮收尾还报一次「流中断」（#101 第四条）。
- **无障碍读不到**：小丑牌是游戏引擎自己画的，`screen_read` 读出 0 个元素，只能看图。
- 打法上也有失误（只剩两次出牌还差三千多分，打了一张高牌）。这是模型的事，不是这份要解决的。

## 核心：拆成三层，各走各的节奏

现在一轮里要做完「看 → 想 → 点 → 说」，最慢的一环拖住所有环。拆开：

```
 画面 ──► 眼睛（小模型） ──► 牌局状态 JSON ──► 手（她出牌）
                         │
                         └─► 事件流 ──► 嘴（三个人解说、语音）
```

| 层 | 做什么 | 快慢 |
|---|---|---|
| 眼睛 | 截图 → 小模型 → 牌局状态（每张手牌的点数、花色、增强、是否被削弱、坐标；分数、目标、剩余出牌和弃牌、钱、底注）。和上一帧比，变了就发事件 | 一帧几十到几百毫秒 |
| 手 | 她拿到的是文字状态，不是图；回「选第 1、3、5 张，出牌」；执行器换算成点按，点完由眼睛核对 | 一步一次模型调用 |
| 嘴 | 听事件说一两句；谁说、说多少、过期的丢掉 | 和手并行 |

### 一、眼睛：小模型

- **输入**：截图。现在 `screenshot` 存的是缩到 1280 的 JPEG，牌角 20 来像素。识别用的那张要能拿**原尺寸**（3168×1440），或者至少只截手牌那一块的原尺寸。要改 `device-mcp` 的截图。
- **输出**（第一期只认这些）：
  ```json
  {"screen":"play","blind":{"name":"窗口","target":4000},"score":1368,
   "hands_left":1,"discards_left":1,"money":13,"ante":3,"round":8,
   "hand":[{"rank":"A","suit":"C","enh":null,"debuffed":false,"selected":false,"x":1083,"y":975}, ...],
   "jokers":[{"slot":1,"x":...,"y":...}], "seq":42}
  ```
  `screen` 先分几类：选盲注、出牌、商店、开包、结算、主菜单。小丑牌第一期只认位置、不认是哪张（一百多种），名字让她自己看图；第二期再认。
- **模型**：一个小的检测模型（YOLO 一类的 nano 档）框出牌、按钮、数字栏，加一个小分类器认牌角的点数和花色；数字用模板也行。小丑牌是像素画、图案固定，这类模型很容易训准。
- **数据**：先用模板匹配自动标（小克 11-04 试过：手牌等距排开，从 1280 图里把 8 张牌的左上角裁出来放大，点数、花色、削弱的粉红斜条、金色底都清楚），人工改错，再加游戏「牌组」页一屏截全 52 张；训练时加缩放、亮度、动画中间帧的扰动。
- **在哪训、在哪跑**：在主人电脑上训（RTX 5060）。推理放哪里**要量了再定**：放电脑上，手机经已有的电脑中转发图过去，一来一回局域网几十毫秒，但出门就用不了；放手机上（ONNX / NCNN），要先确认手机上能装推理库。小克手机上现在有 numpy，图片靠 ffmpeg 解码；Pillow 要主人先在「扩展 → 工具包模块」装「文档与数据」；OpenCV 只在 x11 仓库里。
- **第一期过渡**：模型训出来之前，眼睛先用模板匹配顶上，接口不变，后面换模型时上面两层不用动。

### 二、手：她出牌

- 新工具（进 `device-mcp` 或单开 `game-mcp`）：
  - `game_state` → 上面那份 JSON（文字，不带图）。
  - `game_act {select:[1,3,5], then:"play"|"discard"}`、`game_act {tap:"next_round"|"skip_blind"|...}` → 执行器按坐标连点，点完等画面停稳（小丑牌出牌有动画），用眼睛核对选中了没有，返回新状态。
  - 认不出的画面就回 `screen:"unknown"`，她自己截图看。
- 这样她一步只要一次模型调用，选几张牌也不再是几次点按、几个来回。
- **和 `presence.md` 第二节对一下**：那里写「她在自己会话里调这些工具就是在操作，不另写一套操作循环」。这份照这个做：还是她在自己那段会话里调工具出牌，只是多了两件更顺手的工具，不另起一个替她玩的程序。
- **节奏旋钮**（主人要能调）：两步之间最少隔几秒（给观众看清）；一轮里最多连走几步再停下说话；要不要每步都说一句。

### 三、嘴：解说和语音

- 眼睛发的事件进 `presence.md` 说的那条事件流：`publish({type:"xk", op:"game", ev:"hand_played", hand:"同花", score:2140, seq:43, ...})`。事件只记发生了什么，不带评论。
- **谁说**：打的那个人边打边说（她的话就是她这一轮的 `delta`）；另外两个在聊天室里听事件，有看头的事件（打出大牌型、过关、翻车、商店买了小丑）才有机会插一句，沿用 #61 的接话规则和上限。
- **说得短、说得新**：
  - 每句话带上它说的是哪一刻（`seq`）。语音排队时，牌局已经往前走了好几步的话，这句就不念了，文字照样留在群里。
  - 平板念的时候新句子能插到前面；主人开口时打断正在念的。
  - 群页把游戏事件显示成一行灰字（「哈基米打出同花 +2140」），不用她们再口头报账。战报交给事件，嘴只管反应和吐槽。
- **和主人 11-02 定的第 2 条对一下**：「她什么时候开口、说多少，跟人设走，不写『玩的时候安静』这类规则」。上面的「过期不念」「事件有看头才插话」是在管节奏，会碰到这一条。主人 11-04 说要「方便调整你们玩游戏和说话的节奏」，所以做成**主人手上的旋钮、默认放宽**，不写进她们的提示词。**要主人确认**这样算不算改了第 2 条。
